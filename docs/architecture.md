# Архитектура

## Структура

```text
hr_frontend/src/
  App.tsx                маршруты и ограничения экранов по режиму
  components/            общий интерфейс SAQ, шапка, меню, UI
  modules/hr/pages/      предметные экраны обучения и кадров
  api/types.ts           контракты сущностей
  api/storage.ts         версионное хранилище JSON и IndexedDB-файлы
  data/seed.ts           демонстрационные данные
  store/HrContext.tsx    команды приложения и синхронизация состояния
  store/hrDomain.ts      проверка правил, попытки, оценивание, прогресс
  utils/                 импорт/экспорт и общие функции
```

React, TypeScript, Vite, BrowserRouter, lucide-react, Inter; предметные страницы отделены от общих компонентов и модели данных. Стиль и организация взяты за ориентир из `saq-prof-control-demo`, без изменения рабочего репозитория разработчиков.

## Данные

Сотрудник, курс, глава, урок, программа, назначение, тест, вопрос, попытка, результат ручной проверки, библиотечный ресурс, отзыв и уведомление связаны устойчивыми ID. Проценты и статусы рассчитываются из фактических уроков и попыток. При начале теста фиксируются копия теста, порядок вопросов и время окончания.

Версия состояния — `saq-hr:v1`; роль и выбранный сотрудник — отдельное состояние интерфейса. Файлы хранятся Blob в IndexedDB. Локальное сохранение не гарантирует резервное копирование: очистка данных браузера удалит данные и вложения. При нехватке места интерфейс сообщает об ошибке сохранения. Исходное повреждённое состояние сохраняется для восстановления перед записью нового набора.

## Перед промышленным применением

- Подключить существующую серверную авторизацию SAQ/SSO и справочник сотрудников. Роль нельзя доверять переключателю frontend.
- Перенести команды `HrContext` в серверные API с проверкой принадлежности назначений, HR-полномочий и журналированием.
- Хранить вопросы с правильными ответами только на сервере; на клиент выдавать разрешённый набор. В макете правильные ответы доступны в исходном JS, поэтому он непригоден для защищённой аттестации.
- Фиксировать начало/срок/порядок попытки и оценивать ответы на сервере. Время клиентского устройства не является доверенным.
- Подключить БД, объектное хранилище файлов, резервное копирование, ограничения загрузок и проверку файлов.
- Выполнять напоминания по расписанию на сервере; локальный макет не рассылает email и не работает в фоне при закрытом браузере.
- Подключить ИИ отдельно: доступ администратора, защищённый backend, лимиты и аудит. Ключи не помещать в `VITE_*` и публичные исходники. Не выдавать демонстрационный текст за ответ модели.
- Реестр сертификатов, подлинность, срок действия, последовательность учебных программ и повторное ежегодное обучение согласовать отдельными бизнес-правилами.

Макет можно опубликовать на Vercel без backend для согласования интерфейса и сценариев. Его пользовательские данные останутся локальными для каждого браузера.
